Overview / Hand-off contract
Step C.3 · HALT if A produced zero outputs

The outputs.traefikIngresses[] hand-off

Phase A's state file is the only bridge between the two phases. The orchestrator copies four fields out of it into the chain's index.yaml, then hands the state path to phase B verbatim.

C.3 · Fields copied from A's state.yaml

Source (A's state.yaml)Destination (chain index.yaml)
outputs.traefikIngresses[]phaseA.traefikIngresses
steps."10".statusphaseA.cutover.status
A's state pathphaseA.statePath
A's report pathphaseA.reportPath
⛔ HALT if traefikIngresses[] is empty — phase A produced no outputs, so phase B would have nothing to convert.

C.4 · How phase B consumes the hand-off

Skill B (gateway-api-migration) is spawned with the state path — not the copied data — so its classifier reads A's outputs fresh. The orchestrator never re-validates them itself:

gateway-migrate common.service/overlays/<env> \
  --source-class traefik \      # convert the Ingresses A just created, not nginx ones
  --no-redirect \                # A already handled the cutover semantics
  --gateway-class <chosen> \     # from C.1: traefik (default) or gke-l7-global-external-managed
  --source-state <index.yaml.phaseA.statePath>

--skip-a · Supplying the hand-off manually

When phase A was already done in an earlier session, --skip-a skips C.2 — but the contract still must be satisfied:

  • Operator must pass --phase-a-state <path> pointing at a completed skill A state.yaml
  • The file must have verdict: COMPLETE
  • It must contain at least one outputs.traefikIngresses[] entry
  • HALT otherwise
