Per-phase state files + the chain index.yaml

Three documents, three owners. Each sub-skill keeps its own state file and report; the chain's index.yaml records only statuses, paths, the copied hand-off, and the verdict.

C.5 · Combined index.md + verdict rules

The human-readable index is rendered from references/chain-report-template.md by substituting {{ ... }} variables from index.yaml, and written to index.md alongside it. It links both sub-reports — it does not duplicate them.

  • PASS — both phases completed
  • COMPLETED_WITH_MANUAL_REVIEW — any sub-skill had WARN-level findings
  • COMPLETED_A_ONLY — --skip-b was passed
  • FAIL — otherwise
Path note — v1.11.0 vs v2.0.0: in v1.11.0 phase B writes to docs/reports/gateway-migration/; after the v2.0.0 rename it becomes docs/reports/ingress-to-gateway/. The chain records whichever the sub-skill produces — no special-casing.
