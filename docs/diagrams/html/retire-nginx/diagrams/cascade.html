Controller removal — the cascade chain

Deleting one file in Git is sufficient to remove the entire nginx controller from the cluster. ArgoCD does all the work.

1 · Repo: delete the Application yaml

rm common.ingress/argocd/<env>.yaml — the only file the skill removes for the controller.

2 · app-of-apps syncs with prune: true

The parent app sees the manifest gone and prunes the Application object from the cluster.

3 · Application finalizer fires

resources-finalizer.argocd.argoproj.io blocks deletion until the app's resources are cleaned up.

4 · Cluster: controller resources cascade away

nginx controller Deployment, Service, ConfigMap, and RBAC are deleted by the finalizer — no manual kubectl delete, no helm uninstall.

Why the overlay directory is left alone

common.ingress/overlays/<env>/ becomes dead code the moment the Application yaml is gone — nothing references it. Leaving it is harmless; deleting it is a follow-up-commit nicety, not a correctness requirement.

✓ KEEP common.ingress/base/ and the other envs' argocd/*.yaml — remaining environments still deploy from them. Only after retire-nginx all does Step 7 offer to archive the whole module.

Post-merge verification

kubectl get pods -n ingress-nginx   # expect: 0 pods after ArgoCD sync
# monitor: no 502s — all traffic through Traefik / HTTPRoutes
