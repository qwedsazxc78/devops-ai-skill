Overview / $patch: delete
Step 5c · overlay-only · base files untouched

$patch: delete

Excludes base nginx Ingress resources from one env's render without editing the base — other environments still using those files keep rendering them.

The patch appended to the overlay kustomization

# common.service/overlays/<env>/kustomization.yaml
patches:
  # Nginx ingress retirement (<env>): replaced by Traefik/HTTPRoutes
  - patch: |-
      $patch: delete
      apiVersion: networking.k8s.io/v1
      kind: Ingress
      metadata:
        name: <resource-name>
    target:
      kind: Ingress
      name: <resource-name>
📌 namePrefix: target names are the original names — Kustomize applies patches before the namePrefix: <env>- transformation. Section order: if the kustomization has a configurations: block, patches go before it.

Names come from kustomize build, not file names

kustomize build common.service/base \
  | awk '/^kind: Ingress/{f=1} f && /^  name:/{n=$2}
         f && /ingress.class: nginx/{print n} /^---/{f=0}'
# file names don't always match resource names — render and extract

Special case: class-override patches (GCE / ALB)

If an env overlay patches a base nginx Ingress to a different class (e.g. ingress.class: gce for a GCE external LB), that resource must stay rendered:

  • Keep the patch file under patches: — it owns the class override
  • Do not add $patch: delete for that resource name
  • Rename only the file for clarity (n8n-nginx-ingress.yaml → n8n-gce-ingress.yaml) — never metadata.name
⛔ Renaming the K8s resource deletes + recreates the Ingress, which reprovisions the cloud LB (downtime). And Kustomize rejects $patch: delete + a same-name standalone resource — duplicate resource IDs error at accumulation, before patches even run.
