Step 6 · halt means no commit

Validation — the right zero

The retirement target is nginx-class resources, not all kind: Ingress. Envs with Traefik Ingresses legitimately keep Ingress resources after retirement.

6a · nginx-class count must be zero

kustomize build common.service/overlays/<env> \
  | grep -c "ingress.class: nginx\|ingressClassName: nginx"
# Expected: 0   — do NOT check total `kind: Ingress` count
🛑 Non-zero? Identify the survivor, report, and halt — never commit a partially-retired overlay.

6b · Remaining Ingresses are non-nginx

kustomize build common.service/overlays/<env> \
  | awk '/^kind: Ingress/{f=1} f && /^  name:/{print $2} /^---/{f=0}'
# all names should be *-traefik-* or other non-nginx resources

6c · Regression — every other env still builds

for other_env in dev stg prd; do
  [ "$other_env" = "<env>" ] && continue
  kustomize build common.service/overlays/$other_env > /dev/null \
    && echo "$other_env: PASS" || echo "$other_env: FAIL"
done

Base files are shared — a $patch: delete mistake in one env's overlay can't break others, but deleting an orphan file that wasn't truly orphaned can. The regression build catches it before commit.

✓ All three checks pass → Step 8 prints the summary and the suggested commit message: retire(nginx/<env>): remove controller app + exclude base nginx Ingress resources
