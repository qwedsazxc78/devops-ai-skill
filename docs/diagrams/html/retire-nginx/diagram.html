nginx-ingress-retire

Post-migration cleanup: retire the nginx ingress controller (common.ingress) and all nginx Ingress resources (common.service) per environment — only after Traefik / Gateway API replacements are live and DNS has been cut over. Safety-gated at every step.

devops:zeus · *retire-nginx · detailed 🧠 Mindmap explainer
Eight-step pipeline — red borders are abort gates
Step 1
Parse args
dev | stg | prd | all. No arg → interactive env detection from overlays/.
Step 2 · Gate
Pre-flight
Build must pass. Inventory nginx vs Traefik vs HTTPRoute. Abort if no replacements exist.
Step 3
Discovery
Controller app yaml, base Ingress names via kustomize build (not grep), orphans, archive/.
Step 4 · Gate
Plan + confirm
Full DELETE / PATCH / KEEP plan shown. Nothing happens without explicit operator yes.
Step 5
Execute
Delete controller app yaml · $patch: delete base nginx Ingresses · rm orphans + archive/.
Step 6 · Gate
Validate
nginx-class count must be 0 (not Ingress total). All other envs must still build. Halt → no commit.
Step 7
All-env cleanup
After `all`: offer to archive the fully-orphaned common.ingress/ module + unused base files.
Step 8
Summary report
Per-env table, files deleted/modified/kept, regression results, commit message.
Usage
*retire-nginx # interactive — detect envs, ask
*retire-nginx dev # retire one environment
*retire-nginx all # dev → stg → prd, validate each before the next
