*nginx-to-traefik

Swaps ingressClassName from nginx to traefik across one environment's service Ingresses. DNS stays intact — both controllers are live at S1, so traffic shifts seamlessly to Traefik.

What it does

  • Scans all Ingress objects in the target overlay (e.g. overlays/dev)
  • Patches spec.ingressClassName from nginx → traefik
  • Removes deprecated kubernetes.io/ingress.class annotation if present
  • Commits the patch to the overlay; ArgoCD syncs and Traefik picks up the Ingresses
  • Does NOT touch HTTPRoutes — Ingress API is preserved; use *nginx-to-gateway for full Gateway API chain

Before / after — ingressClassName

# Before (S1)
spec:
    ingressClassName: nginx
  rules: ...

# After (S2)
spec:
    ingressClassName: traefik
  rules: ...

DNS reversibility

Because nginx is still running at S1/S2, reverting ingressClassName back to nginx instantly redirects traffic back. No DNS TTL propagation needed. This is the safety property of the dual-controller S1 state.

Parallel run option

With --parallel, Zeus processes multiple service overlays concurrently. Recommended for repos with many services. Each service is committed as a separate ArgoCD sync wave to avoid thundering-herd on the Traefik admission webhook.

Next steps from S2

  • *ingress-to-gateway <module> — upgrades Ingress → HTTPRoute per module (auto-detects source class)
  • *nginx-to-gateway <env> — skips Traefik Ingress and goes straight to full Gateway API chain
