nginx-to-traefik

Class-swap migration: port a batch of services from NGINX Ingress to Traefik Ingress (ingressClassName: traefik) while both controllers keep running in parallel. DNS A-records are the only cutover lever. First half of the chained NGINX → Traefik → Gateway API migration — its state.yaml output feeds gateway-api-migration --source-class traefik.

devops:zeus · *nginx-to-traefik · detailed
Thirteen-step pipeline (0 → 10) — red borders are halt gates
Step 0 / 0b · Gate
Tools + env-config
command -v kustomize yq git. Then prompt operator for Traefik + nginx LB IPs — never derived from the cluster.
Step 1 · Gate
Inventory
inventory_nginx_ingresses.py per env overlay, filtered to ingressClass == nginx. Halt if zero found.
Step 2 · Gate
Batch plan + y/N
Group by host TLD + criticality. b1 = read-mostly, b2 = write-heavy. Halt on operator decline.
Step 3
Generate Traefik Ingress
generate_traefik_ingress.py emits <service>-traefik-ingress.yaml. WARNs + SHA256 recorded in state.yaml.
Step 4
Archive nginx file
git mv <service>-nginx-ingress.yaml → archive/ (never deleted). Pre-edit path saved to state.yaml.backups[].
Step 5 + 6
Kustomization + cert edits
Add Traefik file to resources:, drop nginx from patches:. Add hosts to common.traefik app.ingress.yaml managed cert.
Step 7 / 7b · Gate
Build + consistency
kustomize build both modules; failure rolls back steps 4–6 via git restore. Then 4-way DNS↔verify↔ingress↔cert check.
Step 8 + 9
DNS + verify scripts
Append hosts to HOSTS_<ENV>_<BATCH> in dns-create-traefik.sh and URLs to verify-traefik-<env>.sh (idempotent).
Step 10
Commit msg + runbook
Print file list + Conventional Commits zh-TW message — never auto-commit. Point operator at dns-cutover-runbook.md.
Usage
*nginx-to-traefik # interactive: inventory + propose batches
*nginx-to-traefik dev # process all services in one env
*nginx-to-traefik dev b1 # named batch (b1 | b2)
*nginx-to-traefik dev grafana # single service
*nginx-to-traefik --resume # continue from state.yaml failed step
