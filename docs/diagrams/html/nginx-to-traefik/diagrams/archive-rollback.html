Archive & rollback pattern

nginx files are moved, never deleted — and every move is recorded so a failed build can restore the repo to its pre-run shape with plain git restore.

Step 4 · git mv to archive/

git mv <service>-nginx-ingress.yaml archive/
# HALT if the file is already under archive/ (double-run guard)

The pre-edit path is captured before the move:

backups:
  - { path: argocd-nginx-ingress.yaml, restorePath: archive/argocd-nginx-ingress.yaml }
  • History stays intact — git mv preserves the file and its log.
  • Rollback or audit can always recover the exact nginx Ingress that was retired.

Step 7 · kustomize build gate with rollback

kustomize build common.service/overlays/<env> > /tmp/svc-build.yaml
kustomize build common.traefik/overlays/<env> > /tmp/traefik-build.yaml
# non-zero exit → HALT and roll back steps 4–6 via git restore of backed-up files

Both modules must render: the service overlay (new Traefik Ingress in resources:) and the Traefik controller overlay (updated managed-cert host list).

Step 7b · 4-way cross-consistency check

validate_cross_consistency.sh # DNS ↔ verify ↔ ingress ↔ cert
# non-zero exit → HALT; stderr stale-host list goes into the report

The four host sources — the DNS script, the verify script, the rendered Ingresses, and the managed-cert host list — must agree before the run may continue.
