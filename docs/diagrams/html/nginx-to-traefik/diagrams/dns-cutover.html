DNS A-record cutover & LB IP rules

Both controllers run in parallel for the whole migration. Nothing the skill writes moves traffic — the operator flips DNS A-records from the nginx LB IP to the Traefik LB IP after the commit lands.

Step 0b · Operator-declared LB IPs (invariant §5.3)

The skill reads references/nginx-to-traefik-env-config.md. If state.yaml.envConfig is missing entries for the target env, it issues the 5 prompts from the reference and writes the answers back:

envConfig:
  capturedAt: <iso>
  envs:
    dev: { nginxLbIp: ..., traefikLbIp: ..., certIssuer: ...,
           managedCertNamespace: ..., managedCertResourceName: ... }
⛔ Never derive LB IPs from any cluster resource — invariant §5.3 from the spec. The operator declares them, or the run halts when they decline.

Step 8 · DNS script update

# scripts/dns-create-traefik.sh — find or create the batch array
HOSTS_DEV_B1=(
  "argocd.dev.example.com"
  "grafana.dev.example.com"   # grep -q before append → idempotent
)
# the diff is recorded in state.yaml.steps["8"]

Array name pattern: HOSTS_<ENV_UPPER>_<BATCH_UPPER>. Each new host is inserted only if not already present.

Step 9 · Verify script update

# scripts/verify-traefik-<env>.sh — same idempotent pattern
URLS_<ENV>_<BATCH>=(
  "https://argocd.dev.example.com/"   # URL format: https://<host>/
)

Step 10 · Hand back to the operator

The skill never auto-commits. At the end of a run it prints:

  • The full set of files touched — Step 3 outputs, Step 4 moves, Step 5/6 edits, Step 8/9 edits.
  • A suggested commit message in Conventional Commits zh-TW style.
  • A pointer to references/dns-cutover-runbook.md to follow after the commit lands.

⚠ Until DNS is flipped, the nginx controller keeps serving the migrated hosts — that is the safety property of the class-swap design, and it is why wrong LB IPs (e.g. auto-derived ones) are the most dangerous failure mode.
