Decision order: veto → shortcut → score bands

The decision matrix maps (vetoed, sourceClass, totalScore) to (path, suggestedCommand). Rules are evaluated in order — first match wins. The matrix is plain markdown parsed at runtime; band thresholds change via PR, not code.

Rule 1 · Critical-tier veto — policy, not a flag

Any service whose tier in docs/ingress-tier-map.yaml is critical is forced to defer regardless of score. There is no --force-critical bypass flag — to migrate a critical service, the team PRs the tier map first.

decisions:
  - service: argocd-server
    path: defer
    advisoryPath: two-step      # what the score would have said — kept for the report
    vetoReason: critical-tier
    suggestedCommand: null
⛔ Even --target-path cannot override the veto — the override only rebinds non-vetoed services.

Rule 2 · sourceClass shortcut (traefik)

Services already on Traefik Ingress (sourceClass == traefik) auto-route to direct-gateway regardless of score — the class swap is already done, only the resource swap remains. Suggested command adds --no-redirect:

# traefik-source → resource swap only
*gateway-migrate <module> --source-class traefik --gateway-class traefik --no-redirect

Rule 3 · Foreign class → defer

sourceClass == foreign (e.g. a gce Ingress) returns path: defer with vetoReason: foreign-class — out of scope for the nginx → traefik → gateway migration path.

The --target-path override

  • Valid values: direct-gateway, two-step, swap-only
  • The critical-tier veto still applies (critical services still defer)
  • The traefik sourceClass shortcut still applies
  • All other services are bound to the override path; scoring still runs and advisoryPath records what the score would have said, so the report shows both
  • Recorded as decision.overrideReason: "--target-path <value>"
