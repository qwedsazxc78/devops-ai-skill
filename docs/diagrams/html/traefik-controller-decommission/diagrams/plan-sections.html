Step 5 · generate_decommission_plan.sh · plan-only

The three-section decommission plan

The script renders plan.md (operator-readable) and commands.sh (copy-paste-ready, never auto-executed). The plan is GitOps-shaped: Git is the lever, ArgoCD's pruner does the deleting — helm uninstall never appears.

Inputs (env vars from Steps 1–2)

VariableSource
NGINX_MODULEStep 1 discovery, e.g. common.ingress-nginx
ARGOCD_APP_MANIFESTSComma-separated ArgoCD app YAML paths from Step 1
NGINX_NAMESPACEDestination namespace from Step 1
GCP_PROJECTStep 2 input, or a <TODO> placeholder
REPORT_DIRAbsolute path to the report directory

5a · Archive the Kustomize module

# Make sure we're on the deployment branch
git checkout main && git pull

# Move the entire ingress-nginx module under archive/
git mv common.ingress-nginx/ archive/

# ArgoCD sees the deleted resources and prunes them
git commit -m "chore(ingress-nginx): archive controller module for decommission"
git push

5b · Disable + delete the ArgoCD Application

Per environment (dev → stg → prd, or the operator's preferred order):

# Disable auto-sync so ArgoCD doesn't try to recreate
kubectl patch application <nginx-app-name> -n argocd --type merge \
  -p '{"spec":{"syncPolicy":{"automated":null}}}'

# Explicit prune sync — deletes Deployment, Service, RBAC,
# ServiceAccount, Helm Secret, etc. via ArgoCD's pruner
kubectl patch application <nginx-app-name> -n argocd --type merge \
  -p '{"operation":{"sync":{"prune":true,"force":true}}}'

# Wait for the prune, then remove the Application manifest itself
kubectl wait application <nginx-app-name> -n argocd \
  --for=condition=Healthy=False --timeout=5m || true
kubectl delete -f common.ingress-nginx/argocd/<env>.yaml

# Verify zero resources remain, then optionally drop the namespace
kubectl get all -n <nginx-namespace>
kubectl delete namespace <nginx-namespace>

5c · Optional: LB IP release + IAM cleanup

  • gcloud compute addresses list, then delete the nginx LB IP only after confirming no forwarding rule still references it.
  • Service-account enumeration + IAM binding cleanup.
  • Skipped entirely with --no-lb-cleanup; written with <TODO> placeholders when no GCP project was given.
⛔ Releasing the LB IP is irreversible — that address goes back to the pool. This section exists in the plan precisely so it happens last, after the prune has been verified.
