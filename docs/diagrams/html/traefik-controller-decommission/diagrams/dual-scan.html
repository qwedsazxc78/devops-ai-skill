Dual cluster + repo scan

One scan is not enough: the cluster shows what is live right now, the repo shows what ArgoCD will reconcile back. Both must be clean of nginx-class Ingresses before any decommission plan is generated.

Scan 1 · Live cluster

kubectl get ingress -A
# every Ingress checked against the precedence-aware rule
# kubectl missing → scan skipped, WARN records a degraded state

The cluster scan catches stale, hand-applied, or drifted Ingresses that exist in the cluster but not in Git.

Scan 2 · Repo (rendered, not grepped)

# for every module overlay:
kustomize build common.*/overlays/<env>/
# extract Ingresses where
spec.ingressClassName == "nginx"
#   OR (spec.ingressClassName == null
#       AND kubernetes.io/ingress.class == "nginx")

Rendering every overlay means patches, name prefixes, and generators are all applied before the check — the same manifests ArgoCD would sync.

Exit codes

ExitMeaningEffect
0✓ PASSBoth scans clean — pipeline proceeds to the DNS bake gate
1⛔ BLOCKEDAt least one nginx Ingress still active — HALT with the offending list; commands.sh NOT written
2⚠ DEGRADEDAt least one scan could not run (e.g. no kubectl) — recorded in the verdict
⛔ On BLOCKED, the operator either re-migrates the leftover service or deletes the stale Ingress before retrying. The skill never deletes it for them.
