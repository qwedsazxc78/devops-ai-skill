traefik-controller-decommission

GitOps-safe uninstall planner for the ingress-nginx controller in a Kustomize + ArgoCD repo. Verifies cluster + repo are free of nginx-class Ingresses (precedence-aware), gates on a 72h DNS bake, then emits a plan: archive the module, disable the ArgoCD Application, let ArgoCD prune, optional LB/IAM cleanup. It writes commands.sh — it never executes it, and never runs helm uninstall.

devops:zeus · *decommission-nginx · detailed
Seven-step pipeline (Steps 0–6) — red borders are halt gates
Step 0
Tool check
kustomize · yq · git · jq required. kubectl + gcloud optional — WARN only, skill works offline.
Step 1 · Gate
Module discovery
Find the kustomization with an ingress-nginx helmCharts block + its ArgoCD app manifests. HALT if 0 or >1 matches (use --module).
Step 2
Operator inputs
ISO date · operator handle · migration cycle slug · optional GCP project for LB cleanup.
Step 3 · Gate
Zero-nginx verify
Dual cluster + repo scan. Exit 1 = BLOCKED → HALT, commands.sh NOT written. Exit 2 = DEGRADED.
Step 4 · Gate
DNS bake confirm
Cutover ≥72h ago, every hostname HTTP 200 via Traefik LB, zero nginx-LB traffic? Anything but yes → BLOCKED.
Step 5
Generate plan
Render plan.md + commands.sh: 5a archive module · 5b ArgoCD disable + prune · 5c optional LB/IAM cleanup.
Step 6
State + verdict
Write state.yaml + verify.json. Print READY / BLOCKED / NEEDS_REVIEW / DEGRADED + next-step instructions.
Usage
*decommission-nginx # interactive
*decommission-nginx --cycle prod-batch-3 # named migration cycle
*decommission-nginx --module <path> # disambiguate when >1 module found
*decommission-nginx --skip-dns-bake # NEEDS_REVIEW verdict; not recommended
*decommission-nginx --no-lb-cleanup # skip the LB IP release plan section
*decommission-nginx --resume <state-path> # continue from state.yaml
