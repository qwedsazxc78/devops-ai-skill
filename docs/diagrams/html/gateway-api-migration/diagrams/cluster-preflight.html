Cluster preflight

This is the step that fails real migrations before they start — missing GatewayClass, wrong CRD version, policy CRDs absent. Fully delegated to scripts/check_cluster_preflight.sh, which embodies references/preflight-checks.md and emits structured JSON.

Invocation — coarse first, per-namespace after Step 1

On first invocation (no state.yaml yet) the script runs without --namespaces as a coarse check. After Step 1 discovers the target namespaces, it re-runs with the discovered list to record per-namespace status:

bash scripts/check_cluster_preflight.sh \
  --namespaces "<space-separated-target-namespaces-from-step-1>"
# exit 0 = success (possibly with WARNs) · exit 2 = any halt
# full JSON stdout written verbatim to state.yaml.environment.cluster

What it checks

  • kubectl reachability and cluster access
  • Gateway API CRDs installed at a usable version
  • GatewayClass existence — checks 3 and 4 are parameterized on --gateway-class (default traefik)
  • Policy CRDs — e.g. gcpbackendpolicies for GKE targets
  • Traefik version probe on traefik* targets
  • Target namespaces (when passed via --namespaces)

Result handling

JSON fieldVerdictBehaviour
halts[] non-empty⛔ HALTPrint the exact halt messages from the JSON. No recovery attempt — fix the cluster and re-run (not --resume).
warnings[] non-empty⚠ ContinueEach warning becomes a risk register entry (report Section 9), severity S2 by default.
clean✓ ProceedContinue to Step 1.
⚠ A warning is promoted to S1 when the migration actually needs the missing CRD — e.g. the source Ingress has CORS annotations and policyCRDs.gcpbackendpolicies: false.

Escape hatches

bash scripts/check_cluster_preflight.sh --offline
# emits a stub JSON; report header flags the run as offline-verified

bash scripts/check_cluster_preflight.sh --skip-check 4
# bypasses the GKE policy CRD check (user flag: --skip-preflight 4)
# every skip is recorded in state.yaml.environment.cluster.skippedChecks[]
