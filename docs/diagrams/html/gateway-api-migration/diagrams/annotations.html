Annotation translation — three buckets

NGINX Ingress annotations are inventoried by scripts/inventory_annotations.py against the built overlays from Step 1 — so dead-file annotations are excluded and base-to-overlay variance is already patched in. Every entry carries its source file:line and the references/annotation-map.md row number, which has per-target columns (Traefik default, GKE opt-in).

The buckets

BucketVerdictMeaning
translated✓ CleanDirect Gateway API / provider-CRD equivalent emitted.
translatedLossy⚠ LossyTranslated with semantic loss (e.g. proxy-*-timeout values collapse).
stubbed⚠ ManualEmitted as inline # TODO(gateway-migrate) stubs in the generated YAML, linked to a Manual Review item (e.g. server-snippet path denylists).
unknown! ReviewNo mapping known — dropped with a WARN, surfaced in report Section 4.4 with exact source location.
dropInfoℹ InfoIntentionally dropped, informational only.
⚠ Security promotion: an unknown annotation that looks security-relevant (contains "auth", "cors", "security", "cert", "ssl", "tls", "waf") is promoted to severity S1 in the risk register — a human must confirm it is safe to drop before cutover.

Invocation

ls /tmp/gwm/built/*.yaml > /tmp/gwm/inventory-input.txt
python3 scripts/inventory_annotations.py --files-from /tmp/gwm/inventory-input.txt \
  > /tmp/gwm/annotations.json
# raw-fallback mode uses /tmp/gwm/ingress-files.txt instead
# full inventory written to state.yaml.annotations

Per-target translation (resolved at Step 3)

  • Traefik target (traefik*): CORS → Middleware (kind headers) per target namespace; path denylists → Middleware (kind redirectRegex); HTTPRoutes attach them via extensionRef filters in the route's own namespace.
  • GKE target (gke-l7-*): CORS / lossy timeouts → GCPBackendPolicy per backend Service; path denylists remain stubs pointing at Cloud Armor.
  • Other GatewayClass: vanilla Gateway API only — provider policies deferred to manual review and recorded in the risk register.

2.3 · Per-overlay variance check

In built mode, the translated-annotation sets are diffed across the env masters. Any annotation present in one env but missing in another is a variance finding — recorded in state.yaml.annotations.overlayVariance[] and surfaced as S2 in the risk register. Host-count differences between env masters are recorded too (e.g. "dev declares 14 hosts; stg and prd declare 12").
