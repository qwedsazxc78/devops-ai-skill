Overview / Helm

Helm — Chart Releases

Helm releases land application charts onto GKE. Horus pins chart versions in three files and uses *upgrade to perform an atomic 3-file version bump by querying ArtifactHub for the latest chart version.

Purpose

  • Manages workload deployments as Helm releases (ingress controllers, monitoring, apps)
  • Chart versions pinned across values.yaml, Chart.yaml, and a version lock file
  • *upgrade queries ArtifactHub, compares pinned vs latest, proposes a bump
  • Never uses helm uninstall for decommission — uses ArgoCD prune instead
ℹ️ Version pinning is intentional: auto-upgrades in production break reproducibility. Horus makes upgrades explicit and reviewable.

Key config — version pin (values.yaml)

# helm/traefik/values.yaml
image:
  registry: docker.io
  repository: traefik/traefik
  tag: "v3.3.4"       # pinned — bumped by *upgrade

# helm/traefik/Chart.yaml
apiVersion: v2
name: traefik-wrapper
dependencies:
  - name: traefik
    version: "32.1.0"    # pinned — bumped by *upgrade
    repository: https://helm.traefik.io/traefik

Dependencies

Helm ≥ 3.14 ArtifactHub API GKE credentials

Horus pipeline touchpoints

  • *upgrade — queries ArtifactHub, shows pinned vs latest diff, proposes atomic 3-file bump
  • *full — lints Helm values, checks release health with helm status
  • *scaffold — generates a new Helm release directory with values.yaml + Chart.yaml stubs
  • *health — runs helm list --all-namespaces and reports failed/pending releases
