Overview / GKE

GKE — Cluster & Workloads

Google Kubernetes Engine receives infrastructure from Terraform and workloads from Helm. Cluster configuration (version, node pools, autoscaling) is managed entirely in Terraform; application releases land via helm upgrade --install.

Purpose

  • Cluster, node pools, and networking provisioned by Terraform (immutable infra)
  • Workloads (ingress controller, monitoring, apps) deployed by Helm releases
  • Cluster outputs (endpoint, CA cert) exposed as Terraform outputs → consumed by Helm provider
  • Node pools: standard + spot (Spot VMs for batch/dev; standard for prod services)

Key config — Terraform cluster outputs

# modules/gke/outputs.tf
output "cluster_endpoint" {
  value     = google_container_cluster.primary.endpoint
  sensitive = true
}
output "cluster_ca_certificate" {
  value     = google_container_cluster.primary.master_auth[0].cluster_ca_certificate
  sensitive = true
}
# Consumed by: helm provider data source

Node pool configuration

# modules/gke/node_pools.tf (excerpt)
node_pools = [
  {
    name           = "default-pool"
    machine_type   = "e2-standard-4"
    min_count      = 1
    max_count      = 5
    auto_upgrade   = true
  },
  {
    name           = "spot-pool"
    machine_type   = "e2-standard-4"
    spot           = true
    min_count      = 0
    max_count      = 10
  }
]

Dependencies

Google Cloud project + billing Terraform GKE module ≥ 31 Helm provider ≥ 2.12

Horus pipeline touchpoints

  • *health — checks node pool status, reports NotReady nodes + failing system pods
  • *full — includes cluster version check + Helm release health scan
  • *cicd — reviews GKE-related pipeline steps (workload identity, docker auth, deploy gates)
