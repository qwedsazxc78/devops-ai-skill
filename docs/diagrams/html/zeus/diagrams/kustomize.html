Overview / Kustomize

Kustomize — base/ + overlays

The Git source of truth. Kustomize renders environment-specific manifests from a shared base/ plus per-env overlay patches, keeping DRY configuration without templating engines.

Purpose

Kustomize assembles Kubernetes manifests declaratively. Zeus uses a two-layer layout:

  • common.service/base/ — shared Deployment, Service, Ingress/HTTPRoute skeletons
  • common.service/overlays/{dev,stg,prd}/ — per-env patches (replica count, image tag, resource limits, ingress host)
  • common.traefik/ — controller plane, rendered separately (needs --enable-helm)

ArgoCD points each Application at one overlay path and runs kustomize build on sync.

Key config — base kustomization.yaml

# common.service/base/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - deployment.yaml
  - service.yaml
  - ingress.yaml     # or httproute.yaml post-migration

Key config — overlay patch (prd)

# common.service/overlays/prd/kustomization.yaml
bases:
  - ../../base
patchesStrategicMerge:
  - replicas-patch.yaml
images:
  - name: my-service
    newTag: "1.4.2"

Dependencies

kubectl kustomize ArgoCD Application No external tools required

Zeus pipeline touchpoints

  • *full — runs kustomize build on every overlay, lints YAML
  • *review — validates overlay patches before merge
  • *scaffold — generates a new service base/ + stub overlays from a template
  • *pre-merge — gates the MR by running build + diff against current state
