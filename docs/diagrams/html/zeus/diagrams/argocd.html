ArgoCD — Application + auto-sync

The GitOps engine. Each environment gets its own ArgoCD Application pointing at the matching Kustomize overlay. ArgoCD watches for Git changes and syncs the cluster to match — automatically, with prune on delete.

Purpose

  • Continuous reconciliation: desired state in Git → actual state in GKE
  • Auto-sync with prune: deleted resources in Git are removed from the cluster
  • Self-heal: if someone manually changes the cluster, ArgoCD reverts it
  • One Application per env (dev/stg/prd) — isolated sync cycles, no blast radius between envs

Key config — Application spec

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: common-service-prd
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/org/gitops-repo
    targetRevision: HEAD
    path: common.service/overlays/prd
  destination:
    server: https://kubernetes.default.svc
    namespace: default
  syncPolicy:
    automated:
      prune: true
      selfHeal: true

Dependencies

ArgoCD ≥ 2.8 Kustomize (bundled) Git repo access GKE credentials (RBAC)

Zeus pipeline touchpoints

  • *full — checks ArgoCD sync status, reports out-of-sync applications
  • *review — diffs the MR against the current Application revision
  • *health — reports all Application health statuses in one table
  • *pre-merge — blocks MR if any Application is Degraded
