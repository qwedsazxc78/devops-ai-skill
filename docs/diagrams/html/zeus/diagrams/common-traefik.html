Overview / common.traefik

common.traefik — Controller Plane

The Traefik ingress controller, managed as a Helm-enabled Kustomize module. This is the controller plane — it owns the admission webhook and processes Ingress + HTTPRoute objects across all namespaces. Kept separate from common.service so controller upgrades don't trigger data-plane re-deploys.

Purpose

  • Provisions the Traefik Deployment, DaemonSet, and RBAC in the traefik namespace
  • Watches IngressClass traefik and GatewayClass resources cluster-wide
  • Separate from common.service: controller lifecycle ≠ data-plane lifecycle
  • Needs --enable-helm in the ArgoCD Application (Helm chart included via Kustomize HelmChartInflationGenerator)

Key config — Kustomize HelmChartInflationGenerator

# common.traefik/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
helmCharts:
  - name: traefik
    repo: https://helm.traefik.io/traefik
    version: "32.1.0"
    namespace: traefik
    valuesFile: values.yaml
⚠️ ArgoCD Application for common.traefik must set spec.source.kustomize.enableHelm: true.

Traefik values snippet

# common.traefik/values.yaml (excerpt)
ingressClass:
  enabled: true
  isDefaultClass: false  # keep nginx as default during S1
providers:
  kubernetesIngress:
    ingressClass: traefik
  kubernetesGateway:
    enabled: true

Dependencies

Traefik Helm chart ≥ v30 ArgoCD --enable-helm GatewayClass CRDs (for HTTPRoute)

Zeus pipeline touchpoints

  • *install-traefik — scaffolds the common.traefik/ module and sets the ArgoCD enable-helm flag
  • *full — validates Helm chart version and Kustomize build
  • *health — checks Traefik pods running + IngressClass present
  • *decommission-nginx — after S3: verifies no Ingresses still point at nginx before proceeding
