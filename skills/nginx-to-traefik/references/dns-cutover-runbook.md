# DNS Cutover Runbook — nginx-to-traefik (class swap)

This runbook is the operator-facing cutover script for skill A. The skill
emits a link to this file at step 10. DNS is the only cutover lever — no LB IP
changes, no nginx Ingress deletions.

## Pre-cutover invariants

Before flipping DNS, all of the following must be true:

1. **Traefik Ingress files exist** alongside nginx Ingresses in
   `common.service/overlays/<env>/` (both classes live in parallel).
2. **`kustomization.yaml` references the new Traefik files** — ArgoCD has
   already reconciled and the Traefik Ingress objects are live in the cluster.
3. **`app.ingress.yaml` updated** — `common.traefik/overlays/<env>/app.ingress.yaml`
   lists all hostnames that the Traefik LB should serve.
4. **`verify-traefik-<env>.sh --pre-cutover` passes** — Traefik serves every
   host via `--resolve` DNS override before any DNS record is touched.
5. **`dns-create-traefik.sh` is committed and reviewed** — the script was
   generated by skill A and validated by the operator. No ad-hoc DNS edits.
6. **LB IPs match `envConfig`** — `envConfig.envs.<env>.traefikLbIp` in
   `state.yaml` equals the Traefik Service `status.loadBalancer.ingress[0].ip`.
   Mismatch means the env-config was captured before the LB was assigned.

## Cutover sequence

1. **Commit phase-A artifacts** — Traefik Ingress files, archived nginx files,
   updated `kustomization.yaml`, updated `app.ingress.yaml`, updated
   `dns-create-traefik.sh` / `verify-traefik-<env>.sh`. All in one commit on
   the migration branch.

2. **ArgoCD reconciles** — merge (or `argocd app sync`) and confirm with:
   ```bash
   kubectl get ingress -A | grep -E "(nginx|traefik)"
   ```
   Both the old nginx Ingress and the new Traefik Ingress objects should appear
   simultaneously. Neither is deleted at this stage.

3. **Pre-cutover smoke test** — run the generated verify script with DNS override
   so traffic goes to the Traefik LB without touching real DNS:
   ```bash
   ./scripts/verify-traefik-<env>.sh --pre-cutover
   ```
   Expected: all hostnames return HTTP 200 via Traefik. Fix any errors before
   proceeding — do not flip DNS with a failing pre-cutover check.

4. **Flip DNS A-records** — run the generated DNS script:
   ```bash
   ./scripts/dns-create-traefik.sh <env>-<batch> --force
   ```
   This updates each hostname's A-record from `nginxLbIp` to `traefikLbIp`.
   The `--force` flag skips the interactive confirmation prompt.

5. **Post-cutover smoke test** — wait for DNS propagation (typically 30–120 s)
   then run:
   ```bash
   ./scripts/verify-traefik-<env>.sh <env>-<batch> --post-cutover
   ```
   Expected: all hostnames resolve to `traefikLbIp` and return HTTP 200.

6. **Soak period** — operator-defined, suggested 24h+. Monitor ingress error
   rate and latency. Skill A records the cutover timestamp in
   `state.yaml.audit[]` for traceability.

7. **Optional cleanup** — after soak, archive or delete the nginx Ingress files.
   Skill A already moved them to `archive/` during phase A execution. A separate
   cleanup commit removes the `archive/` dir when the operator is confident.

## Rollback procedure

DNS only rollback (preferred — no code change needed):
```bash
./scripts/dns-create-nginx.sh <env>-<batch>
```
The operator must keep `dns-create-nginx.sh` in the repo. Skill A does **not**
generate a reverse DNS script; the operator must maintain the original.

Code rollback:
```bash
git revert <commit-sha>
```
This restores the nginx file from `archive/` and removes the Traefik file.
ArgoCD reconciles on the next sync cycle.

## Cross-links to skill C

If this run is phase A of a full nginx→Gateway API chain, skill C records the
cutover state in:
```
docs/reports/nginx-to-gateway/<chain-slug>/index.yaml
  phaseA:
    cutover:
      timestamp: <ISO-8601>
      env: <env>
      batch: <batch>
      status: soaking | complete
```

After the soak period is complete, run skill C to start phase B:
```bash
# Zeus command — skip phase A, go straight to Gateway API migration
*nginx-to-gateway <env> --skip-a
```
Skill C reads `phaseA.cutover.status` and refuses to start phase B if the
value is `soaking` and the soak duration is less than the configured minimum.
