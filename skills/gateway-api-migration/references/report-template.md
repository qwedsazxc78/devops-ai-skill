## 8. TLS / certificate map

Every hostname's TLS configuration, new and old, side by side. This is
the second-most-common source of post-migration surprise (after unknown
annotations).

| Hostname | Cert kind | Cert name | Cert namespace | Listener | Provisioning wait | Status |
|---|---|---|---|---|---|---|
{{tls_rows}}

Cert kinds and expected provisioning waits:

- **`ManagedCertificate`** (GKE) — 15–60 minutes after Gateway
  deployment AND after DNS validation. ManagedCertificate will stay
  `Provisioning` until the hostname resolves to the Gateway IP. This
  means the first cutover for a hostname needs DNS flip *before* the
  cert goes active, which is a chicken-and-egg problem solved by the
  `--resolve` curl test in the runbook.
- **`Secret`** (cert-manager) — 0 minutes, already provisioned if the
  `Certificate` CR is `Ready`.
- **`Secret`** (manually managed) — 0 minutes, already present.

## 13. Rollback commands

### 13.1 During phase 1 (Gateway deployed, no DNS changes)

```bash
# The Gateway is inert — no traffic has been switched. Simply unsync/delete.
argocd app delete {{generated_module}}-dev
argocd app delete {{generated_module}}-stg
argocd app delete {{generated_module}}-prd

# And/or remove the generated module from the repo:
git revert {{pending_commit_sha_or_placeholder}}
```

### 13.2 During phase 2 (HTTPRoutes deployed, no DNS changes)

```bash
# HTTPRoutes are live on the new Gateway but no DNS points to it.
# Unsyncing common.service/ detaches the HTTPRoutes.
argocd app sync common-service-dev --revision <pre-migration-sha>
argocd app sync common-service-stg --revision <pre-migration-sha>
argocd app sync common-service-prd --revision <pre-migration-sha>

# Or manually delete the HTTPRoute resources:
{{httproute_delete_commands}}
```

### 13.3 During phase 3 (DNS cut over for one or more hostnames)

```bash
# For each hostname that needs to revert:
# 1. Flip DNS A/AAAA record back to the original ingress-nginx LB IP.
# 2. Wait for DNS TTL + 1 minute.
# 3. Verify with:
curl --resolve <hostname>:443:<original-nginx-lb-ip> https://<hostname>
```

The old `{{master_module}}/` and minion `*-nginx-ingress.yaml` files
were **never modified** — they are still serving traffic at the
ingress-nginx LB IP. DNS flip is the entire rollback.

### 13.4 Full revert (revert generated module + in-place edits)

```bash
git revert {{pending_commit_sha_or_placeholder}}   # reverts the migration PR
git push origin <branch>
argocd app sync common-service-dev                  # re-sync old state
argocd app sync common-service-stg
argocd app sync common-service-prd
```

If the PR was already merged and squashed, the revert SHA differs —
find it with `git log --grep='migrate.*gateway'`.
